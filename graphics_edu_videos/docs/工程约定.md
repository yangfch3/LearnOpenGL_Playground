# 工程约定

人与 AI 共用。在 `graphics_edu_videos/` 下工作，先读本文与[风格规范](风格规范.md)。

## 黄金准则

1. **先出样片再写文档**：新镜头、新手法先做 10–30s 可看的样片，方向认可后再落到分镜和规范
2. **单一时间源**：每个镜头由一个 `build.py` 算出全部事件时刻，同时生成动画数据和音轨；HTML 只读数据，不写时间常数
3. **验证靠数据，看画面靠用户**：正确性用脚本和 `check` 验证（数值、时刻、溢出、对比度），通过后渲染，交给用户观看反馈。AI 不主动读图（截图、抽帧、拼图），除非用户要求，或出现数据和 `check` 都定位不了的画面问题。音画同步和确定性校验只在交付前跑一次
4. **比喻先复述**：反馈是比喻（如「像扫琴键」）时，先用一句话把它复述成具体的画面动作，确认后再动手
5. **命令不卡、输出不乱**：命令一律非交互（ffmpeg 加 `-nostdin -y`，`hyperframes init` 加 `--non-interactive`）并设超时，长时间无输出先查进程和网络，不盲等；含中文的输出写进 `Temp/` 下的 UTF-8 文件再读，或设 `PYTHONIOENCODING=utf-8`（PowerShell 5.1 终端会乱码）
6. **长文件分段写**：单次写入不超过约 150 行，长文档按节追加；单次过长会被中断
7. **大内容只取所需**：大段命令输出（`check --json`、`audio --json`、渲染日志）用筛选或脚本只取需要的字段；大文件（skills 参考文档、依赖源码、锁文件）先搜索定位再按行读；网页优先看搜索摘要或按关键词抓取，不抓全文

## 1. 目录与文件

- 目录规划见 [README](../README.md)，目录用到再建
- 每集文档放 `docs/<集号>_<中文标题>/`，固定两份：`知识点.md`（受众、依据、关键数据、讲法）、`分镜.md`；成片工程放 `episodes/ep<集号>-<英文名>/`，代码与渲染目录名只用 ASCII
- 跨项目共用的资源（字体、GSAP 等第三方库）只放 `shared/` 一份。HyperFrames 项目经 `tools\link-shared.cmd <项目目录>` 建立的 `assets/shared` 联接引用，如 `assets/shared/fonts/…`、`assets/shared/vendor/gsap/gsap.min.js`；不往项目里复制，不引用 CDN
- 临时文件（探针、草稿、日志、中间渲染）一律放 `Temp/`，按任务分子目录，如 `Temp/s1-probe/`；不用系统临时目录
- 不入库：`Temp/`、渲染产物、`node_modules/`、`.venv/`；字体、WAV 走 Git LFS

## 2. 工具调用

- 命令在 `graphics_edu_videos/` 下执行
- HyperFrames：用 `npx hyperframes`（取 `package-lock.json` 锁定版本）；不用 `@latest` 或其他版本号
- Manim：一律经 `tools\manim.cmd` 启动（原因见第 4 节）
- Python：用 `uv run`，不往系统 Python 装包；镜像沿用 `pyproject.toml` 中配置
- 耗时操作（安装、整段渲染）先说明目的与目录再执行
- Agent skills：固定在仓库根 `.kiro/skills/`，取自与 HyperFrames 同版本的 git tag；不用 `hyperframes skills update` 或 `npx skills add`（前者装最新 main，且装到用户目录）

## 3. 已验证做法

- WebGPU 镜头：合成根节点加 `data-requires-webgpu`；监听 `hf-seek`，在 `e.detail.waitUntil(...)` 内按 `e.detail.time` 绘制，提交后 `await device.queue.onSubmittedWorkDone()`。同机渲染两次 MP4 字节一致
- `hf-seek` 写法见 skills `hyperframes/references/runtimes.md`；`data-requires-webgpu` 本版 skills 未提及，来自 HyperFrames 源码：声明后渲染前强制检查硬件 device，失败即报错，不静默降级

## 4. 已知问题

- MiKTeX 的 dvisvgm 在进程缺少 `=E:` 这类盘符目录变量时，报 `Windows API error 87`，xdv 转不出 SVG。直接从 PowerShell 或 Python 启动 Manim 都会触发，经 cmd 启动正常，故用 `tools\manim.cmd`
- LaTeX 相关路径（如 Manim `--media_dir`）不能含 `~`：8.3 短路径（如 `ADMINI~1`）会让 xelatex 读文件失败
- `.cmd` 文件用 ASCII + CRLF：首版（UTF-8、中文注释）报「系统找不到指定的路径」，改后正常；编码与换行哪项致错未区分
- 系统 PowerShell 为 5.1：`Set-Content` 不支持 `utf8NoBOM`，写文件用编辑工具
- HyperFrames 不允许资源路径用 `../` 跳出项目根（`invalid_parent_traversal_in_asset_path`，渲染时会被截到项目根内），所以共用资源要经目录联接引用
- 脚手架默认从 CDN 加载 GSAP，网络超时会导致页面报错、时间线缺失；新项目要改成引用 `assets/shared/vendor/gsap/gsap.min.js`
- PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写入 BOM；改文件用编辑工具，或用 .NET 写无 BOM 的 UTF-8
- HyperFrames 遥测已关闭（用户级 `~/.hyperframes/config.json`）；新机器上执行 `npx hyperframes telemetry disable`

## 5. 升级

任一版本变动都要同步改 [README](../README.md) 环境基线。

- HyperFrames：改 `package.json` 版本 → `npm install` → 从同版本 tag 复制 skills（附 LICENSE）→ `npx hyperframes browser ensure` → 重跑 WebGPU 渲染自检
- Manim / Python 依赖：`uv add` / `uv lock --upgrade-package <包>`

## 6. 文本与多语言

当前只做简体中文；英文版预留，届时再定细节。

- 时间轴以中文为准，固定不变
- 镜头按节拍编排：节拍时长集中定义一处，动画与音效按拍内相对时间写，不散写绝对秒数
- 画面文字集中在每集的文本表（zh-CN），镜头代码按键取用，不写死；分镜审定后由分镜抽取生成。文本表格式与加载方式在 A 段 S1 定
- 预渲染片段（Manim、原生 OpenGL、离线 WebGPU）默认不含文字；必须含时，记为「换语言需重渲」
- 英文版启动时再定字体、阅读时长、版式余量。参考：Netflix 成人字幕阅读速度上限为简中 9 字/秒、英文 20 字符/秒（[简中](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide)、[英文](https://partnerhelp.netflixstudios.com/hc/en-us/articles/217350977-English-USA-Timed-Text-Style-Guide)）；本系列中文取 4 字/秒
