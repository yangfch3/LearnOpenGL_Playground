# 工程约定

人与 AI 共用，只管工具、目录、做法与已知的坑。流程与阶段关口见[制作 CheckList](制作CheckList.md)，创作见[创作原则](创作原则.md)，数值底线见[风格规范](风格规范.md)。

## 黄金准则

1. **单一时间源**：每个镜头由一个 `build.py` 算出全部事件时刻，同时生成动画数据和音轨；HTML 只读数据，不写时间常数
   - 几何同理：依附在别的元素上的东西（圈、箭头、高亮、标签），位置直接取被依附元素自身的实际几何，不另用估算公式再算一份。两份算法总有对不上的时候
   - 外形同理：贴图上画的轮廓（圆角、缺口）与承载它的网格用同一组参数生成；一边圆角、一边方角，角上就露出另一层
2. **验证靠数据，看画面靠用户**：正确性用脚本和 `check` 验证（数值、时刻、溢出、对比度），通过后渲染，交给用户观看反馈。AI 少读图：数据证明不了的观感（遮挡、穿帮、构图）才看，只看改动的时刻，拼成一张图读一次。音画同步和确定性校验只在交付前跑一次
3. **命令不卡、输出不乱**：命令一律非交互（ffmpeg 加 `-nostdin -y`，`hyperframes init` 加 `--non-interactive`）并设超时，长时间无输出先查进程和网络，不盲等；含中文的输出写进 `Temp/` 下的 UTF-8 文件再读，或设 `PYTHONIOENCODING=utf-8`（PowerShell 5.1 终端会乱码）
4. **大内容只取所需**：大段命令输出（`check --json`、`audio --json`、渲染日志）用筛选或脚本只取需要的字段；大文件（skills 参考文档、依赖源码、锁文件）先搜索定位再按行读；网页优先看搜索摘要或按关键词抓取，不抓全文
5. **空间也由数据校验**：画面中事物的空间关系与时间一样由数据给出，出片前检查，冲突即报错。衔接跨两套渲染（2D↔3D、Manim↔HyperFrames）时两端都要算，交付前在成片里抽帧实测一次
   - 新增一类画面元素（新样式的文字、新的立体物体）时，同一轮补上它的空间校验。校验只覆盖它知道的东西，漏补时「全部通过」不说明任何问题
   - 查的是创作原则要的东西：焦点不被压、不进字幕带、镜头停住时不被画框切到。不要求所有东西互不相交：那会逼着版面摊开、镜头推远，焦点反而变小
6. **少接缝**：能在同一套渲染、同一个场景里靠参数完成的，不跨渲染器、不换场景。每处接缝都要两端对齐，是穿帮的主要来源
   - 必须跨层时，同一件事只由一份数据决定：如某物何时可见、在哪，两层都读同一个判断，不各写一套条件。各写一套，平时一致，到了边界情况（翻页、转场）就会露馅
7. **错在源头报**：构建脚本对数据加断言（速度、范围、结构），写错当场失败；问题优先在数据层修，渲染放在校验与抽查都通过之后，一次完成

## 1. 目录与文件

- 目录规划见 [README](../README.md)，目录用到再建
- 一部片的 STORYLINES、SPEC 与代码放在同一个工程目录（如 `pilot/<编号>-<工具>/`）；系列有自己的目录约定时见该系列规范。代码与渲染目录名只用 ASCII
- 跨项目共用的资源（字体、GSAP 等第三方库）只放 `shared/` 一份。程序化音效的基础件（噪声、包络、低通、底噪、拨弦、滑音、木琴、闷响、音轨）在 `shared/py/common.py`，各片不再重写；随机源由调用方传入。HyperFrames 项目经 `tools\link-shared.cmd <项目目录>` 建立的 `assets/shared` 联接引用，如 `assets/shared/fonts/…`、`assets/shared/vendor/gsap/gsap.min.js`；不往项目里复制，不引用 CDN
- 临时文件（探针、草稿、日志、中间渲染）一律放 `Temp/`，按任务分子目录，如 `Temp/s1-probe/`；不用系统临时目录
- 不入库：`Temp/`、渲染产物、脚本生成的音轨、`node_modules/`、`.venv/`；字体、非生成的 WAV 走 Git LFS

## 2. 工具调用

- 命令在 `graphics_edu_videos/` 下执行
- HyperFrames：用 `npx hyperframes`（取 `package-lock.json` 锁定版本）；不用 `@latest` 或其他版本号
- Manim：一律经 `tools\manim.cmd` 启动（原因见第 4 节）
- Python：用 `uv run`，不往系统 Python 装包；镜像沿用 `pyproject.toml` 中配置
- 耗时操作（安装、整段渲染）先说明目的与目录再执行
- 长渲染（数分钟以上）只负责启动、确认它真的在走，结果由用户反馈。原因：agent 用命令等待或轮询既占会话，又可能被中断而连带取消渲染
  0. 开渲前先在无头浏览器里加载一次页面，跳到几个时刻，只抓页面报错，不截图。原因：脚本错误要到渲染中途才暴露，代价是整段重来；这一步只要几秒
  1. 用脱离当前终端的后台进程启动，输出写进 `Temp/` 下的日志（挂在 agent 终端上的进程会随终端中断一起被取消）。一律可续渲：设环境变量 `HF_DE_STALL_MS=600000`、`HF_SEGMENTED_CAPTURE=true`，命令加 `--resume`；中断后原命令重跑即跳过已完成的分段（存在 `renders/.hf-segments/`），分段接缝经成片验证无跳帧、闪烁
  2. 先用 4 个 worker；启动后等一小会（约 1 分钟），看一次日志里帧数有没有增长
  3. 帧数不涨或报错，就停掉这个渲染，依次换成 3、2、1 个 worker 重试，每次同样只看一次有没有开始出帧
  4. 确认开始出帧后不再等待、不再查进度：告诉用户 tail 最后几行的命令，渲染后的工作（实测响度、抽帧复核）等用户反馈结果再做
- Agent skills：固定在仓库根 `.kiro/skills/`，取自与 HyperFrames 同版本的 git tag；不用 `hyperframes skills update` 或 `npx skills add`（前者装最新 main，且装到用户目录）

## 3. 已验证做法

- WebGPU 镜头：合成根节点加 `data-requires-webgpu`；监听 `hf-seek`，在 `e.detail.waitUntil(...)` 内按 `e.detail.time` 绘制，提交后 `await device.queue.onSubmittedWorkDone()`。同机渲染两次 MP4 字节一致
- 可校验的逻辑（镜头、姿态、主体位置）写成无 DOM、无 import 的纯模块，浏览器与 node 校验脚本共用同一份；校验脚本的读数据、导入纯模块、区间汇总与写文件用 `shared/js/check.mjs`；校验既查数值有效，也查数据结构完整（如镜头参数个数）
- 3D 镜头用一组连续参数描述（画面中心点、主体平面半高、k = 1/视距、偏航、俯仰；k = 0 即正交），运镜是首尾相接、互不重叠的缓动段。推拉、环绕、正交↔透视都是参数插值，不换相机，就不会跳。投影矩阵 w = 1 + k·u（u 为到主体平面后方的深度），纯模块里同式实现，校验脚本可直接算屏幕位置
- 镜头缩放（像素/单位、视距）按对数插值：s = s₀·(s₁/s₀)^u，推拉观感匀速；线性插值会先快后慢
- 运动模糊：在半帧快门内取若干子帧逐张平均，子帧数按画面每帧位移定（子帧间位移约 ≤ 1.5px），只在镜头快动的帧上开启，耗时也只增加在这些帧上
- 看片觉得「掉帧」时先分清原因：framemd5 查重复帧，对照数据算出的主体屏幕位置查帧滞后；两者都正常，就是运动本身太快（创作原则 §2-17）
- 空间校验逐帧（30Hz）跑，冲突即失败，按区间汇总输出（「何物 @ 起–止」），便于直接定位到时刻
- 斜看的立体物体与纸面文字是否相压，按两者屏幕投影的凸包判（分离轴）；轴对齐包围盒在斜视下大出很多，会把没压到的也报出来
- 角色与动画：
  - 造型简洁分块（盒体关节、无五官或极简五官）；每个肢体两段关节组（髋—膝、肩—肘），关节角由姿态参数给出，不手调顶点
  - 行走不打滑：轨迹为分段匀速路径点，步行相位 = 累计路程 ÷ 半步幅 × π；脚步声用同一公式解出落脚时刻。四足按对角步态相位
  - 2D 侧身转身 = 朝向参数从 +1 连续变到 −1（横向压扁再展开，约 0.25s），在起步前约 0.3s 内完成；站立朝向另列关键帧
  - 动作是带权重的时间窗（角色、动作、起、止），两端渐变后叠加到基础姿态，可与行走同时进行
  - 手持物每帧取手部关节的世界坐标；绳、线每帧重算长度与方向
  - 构建时断言速度上限（参考：人约 ≤ 2.4、猫约 ≤ 3.2 单位/秒）
- 防穿模：建筑、摊位为矩形，石头、树干为圆，角色给半径，30Hz 逐帧查角色与障碍物、角色之间、机位与物体、机位到主体的视线；允许的接触显式豁免。四肢、绳线、手持物查不到，相关时刻抽帧看。群体走位、写实造型与面部表情尚未验证
- `hf-seek` 写法见 skills `hyperframes/references/runtimes.md`；`data-requires-webgpu` 本版 skills 未提及，来自 HyperFrames 源码：声明后渲染前强制检查硬件 device，失败即报错，不静默降级

## 4. 已知问题

- MiKTeX 的 dvisvgm 在进程缺少 `=E:` 这类盘符目录变量时，报 `Windows API error 87`，xdv 转不出 SVG。直接从 PowerShell 或 Python 启动 Manim 都会触发，经 cmd 启动正常，故用 `tools\manim.cmd`
- LaTeX 相关路径（如 Manim `--media_dir`）不能含 `~`：8.3 短路径（如 `ADMINI~1`）会让 xelatex 读文件失败
- `.cmd` 文件用 ASCII + CRLF
- HyperFrames 不允许资源路径用 `../` 跳出项目根（`invalid_parent_traversal_in_asset_path`，渲染时会被截到项目根内），所以共用资源要经目录联接引用
- 脚手架默认从 CDN 加载 GSAP，网络超时会导致页面报错、时间线缺失；新项目要改成引用 `assets/shared/vendor/gsap/gsap.min.js`
- HyperFrames 遥测已关闭（用户级 `~/.hyperframes/config.json`）；新机器上执行 `npx hyperframes telemetry disable`
- 读图工具按路径缓存：覆盖同名图片后再读会拿到旧图，每次另起文件名；新生成的图用小写盘符路径（`e:\`）可能报找不到，改用 `E:/…`
- PowerShell 把 `52.0` 这类数值格式化成 `52`，用数值拼文件名时路径会对不上，拼前先格式化成字符串
- `Start-Process -Wait` 等不到 `npx` 派生的子进程：判断渲染结束要轮询进程或检查输出文件
- `hyperframes check` 的对比度检测按文字元素的框取背景色：框比文字宽（如整屏宽再居中）、背景又不是纯色时会误报。文字框宽度贴合内容（`width: fit-content` 加左右 `margin: auto`）
- HyperFrames 时间线注册须写在内联脚本里：放外部 .js 时 lint 报 `missing_timeline_registry`
- HyperFrames 渲染 WebGL（Three.js）画面时，默认的 fast-capture 会让两次渲染部分帧不一致：渲染加 `--experimental-fast-capture=false`
- HyperFrames 渲染有个停滞看门狗：抓帧数 60s 不涨就判定卡死并中止，失败后临时帧全部删除，无法续接（日志里的 `checkpoint` 只是进度心跳，不是存档）。帧已抓完、编码收尾超过 60s 时也会被误杀（worker 多时易发）。长渲染的做法见第 2 节
- 透明片段：VP9 alpha（yuva420p）与 ProRes 4444 合成后色差 4–6，超过 2；用 MOV 内 PNG（`-c:v png -pix_fmt rgba`），无损，体积约为 qtrle 的 1/4.5
- Manim `add_sound` 的声音晚约 21ms（AAC 编码器前置延迟未补偿）：渲染无声视频，再用 ffmpeg 混入 WAV
- Manim（Cairo）把首个带 updater 的对象之前加入的内容缓存为静态底图，画面不动：updater 挂在最先 `add` 的空对象上
- Manim ThreeDScene：`frame_center` 对 3D 内容重复生效，改为平移场景；屏幕固定对象不能 `become()`；相机旋转矩阵要到截帧时才刷新，updater 里投影前先 `reset_rotation_matrix()`
- XeTeX 不支持可变字体，xeCJK 只能取到 `NotoSansSC-VF.ttf` 的默认实例 wght 100（Thin）；Pango（`Text`）不受影响

## 5. 升级

任一版本变动都要同步改 [README](../README.md) 环境基线。

- HyperFrames：改 `package.json` 版本 → `npm install` → 从同版本 tag 复制 skills（附 LICENSE）→ `npx hyperframes browser ensure` → 重跑 WebGPU 渲染自检
- Manim / Python 依赖：`uv add` / `uv lock --upgrade-package <包>`

## 6. 文本与多语言

当前只做简体中文；英文版预留，届时再定细节。

- 时间轴以中文为准，固定不变
- 镜头按节拍编排：节拍时长集中定义一处，动画与音效按拍内相对时间写，不散写绝对秒数
- 画面文字集中在每部片的文本表（zh-CN，如 `assets/text/zh-CN.js`），构建脚本与镜头代码按键取用，不写死；键名全片唯一，同名会互相覆盖
- 预渲染片段（Manim、原生 OpenGL、离线 WebGPU）默认不含文字；必须含时，记为「换语言需重渲」
- 中文一律走 HyperFrames 文字层，Manim 只出公式与示意图；确需 TeX 内排中文时，用 shared/py/manim_common.cjk_static 从 VF 切静态字重
- 英文版启动时再定字体、阅读时长、版式余量。参考：Netflix 成人字幕阅读速度上限为简中 9 字/秒、英文 20 字符/秒（[简中](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide)、[英文](https://partnerhelp.netflixstudios.com/hc/en-us/articles/217350977-English-USA-Timed-Text-Style-Guide)）；中文取 4 字/秒
