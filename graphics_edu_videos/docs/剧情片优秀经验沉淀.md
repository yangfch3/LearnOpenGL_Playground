# 剧情片优秀经验沉淀

剧情片（无旁白、代码绘制的短片）做到高质量的经验。通用原则见[风格规范](风格规范.md) §6.1 与[工程约定](工程约定.md)黄金准则，本文只记剧情片特有的部分。数值是参考示例，不是硬性规定；具体案例记在[探针记录](试点/探针记录.md)。

## 1. 选题与结构

- **找一条能贯穿全片的规则**：最好的剧情片有一条世界本身在变的规则（如渲染管线一级级打开），故事沿着它推进。观众一旦看懂规则就会预期下一步，每次兑现都是一次满足
- **首尾同一帧**：开场与结尾用同一机位、同一构图，结尾回到开场那一帧再加一层新意。观众自己完成对照，不需要字来点题
- **每段给一个「看清」的对象**：每段都有一样东西从模糊变清楚（一块色斑是猫、一条色带是麦田）。发现感比情节密度更撑得住无旁白的片子
- **配角线短而完整**：交朋友这类配角线有起因、受挫、帮忙、结果四拍即可，每拍一个动作
- **2D 片的规则从平面本身找**：图底关系、线、画框、裁切只在平面上成立。拿它们做规则，2D 才有 3D 替代不了的理由；2D 去模仿 3D 的纵深与光影，处处不如 3D
- **揭示要守住**：结尾若揭示世界更大的样子，把揭示物的范围写进数据，逐帧校验之前的镜头都看不到它。揭示的分量全靠之前没被看见，而漏出一两帧，人工看片很难发现

## 2. 世界

- **一个世界演到底**：所有段落在同一个场景里完成，季节、昼夜、画风都是参数，不另建场景。接缝少，前后比例、位置天然一致
- **世界要小**：主要地点都放进主镜头一帧之内，彼此相距几米到十几米。镜头移动短，人物在各景别都看得清，空间校验也简单
  - 参考：主镜头宽约 16 单位，角色身高约 1.3，最远两个地点相距约 14
- **先定世界规则再摆东西**：如风向一律自右向左，风筝、麦浪、落雪都按它动。规则统一，世界才可信
- **离场要交代**：群众、道具离开画面时要走出去、被收走或被放下，不在镜头里凭空消失；镜头外的状态变化可以不演

## 3. 镜头

- **一台摄像机、一组参数**：推拉、摇移、正交↔透视、环绕都是同一组参数的插值（做法见工程约定 §3），整片没有跳切也不会跳
- **运镜要有被跟随的对象**：摇移跟着一个移动的东西走（跑开的动物、升起的风筝），观众知道为什么要看那边
- **克制在前，强手法在后**：前半段固定机位；第一次推近放在画面细节第一次值得看的时刻，第一次旋转放在有了可以环绕的主体之后
- **景别跟着动作走**：情绪与手上的动作给中近景，人物走位给全景；收尾回到主镜头

## 4. 角色与动画

- **造型简洁、分块**：盒体关节、无五官或极简五官。小误差不显眼，姿态读得清，阴影也干净
- **骨骼**：每个肢体是两段关节组（如髋—膝、肩—肘），关节角由姿态参数给出，不手调顶点
- **行走不打滑**：轨迹为分段匀速路径点；步行相位 = 累计路程 ÷ 半步幅 × π，速度越快摆幅越大。脚步声在构建脚本里用同一公式解出落脚时刻
- **2D 侧身转身 = 横向压扁再展开**：朝向参数从 +1 连续变到 −1，像纸片翻面（约 0.25s）。比交叉淡化自然，角色也一直在画面上
- **转身先于起步**：朝向由每段移动方向自动生成，转身在起步前约 0.3s 内完成；站立时的朝向另列关键帧（面向谁、看什么）
- **动作是带权重的时间窗**：蹲、坐、举、挥手、抬头等写成「角色、动作、起、止」，两端渐变后叠加到基础姿态上，可与行走同时进行，不必为每种组合单独做动画
- **道具挂在手上**：手持物每帧取手部关节的实际世界坐标；绳、线从手连到物体，长度与方向每帧重算
- **动物用同一套思路**：四足按对角步态相位；卧、坐、伸懒腰、扑都是权重
- **速度有上限**：构建时断言各段速度（人约 ≤ 2.4、猫约 ≤ 3.2 单位/秒），路径写错当场报出

## 5. 防穿模

- **占地写进数据**：建筑、摊位为矩形，石头、树干、雪人为圆，角色给半径
- **逐帧校验**：30Hz 检查角色与障碍物、角色之间、角色与群众、透视段机位与物体、机位到主体的视线是否被挡。允许的接触（如动物站在石头上）在规则里显式豁免
- **校验管不到的要看**：四肢、绳线、手持物只靠地面占地查不出，要在相关时刻抽帧看

## 6. 声音

- **声音跟随同一条规则**：画面怎么变，声音也怎么变（如画面分辨率低时音频也降采样降比特），用同一张表驱动
- **一个主题贯穿**：主题旋律不变，音色与空间感随段落升级；结尾回到开头的音色
- **动作都有声音**：落脚、碰撞、拿起放下、转场都配程序化音效，落点取自构建脚本里的节拍

## 7. 流程

1. 写几个故事方向 → 选定 → SPEC：先写清贯穿全片的规则、每段被看清的对象、镜头表
2. 构建脚本先出节拍、布局、轨迹、动作、镜头数据，加断言
3. 场景与角色搭到能出快照，就拼接触表看关键时刻；问题先在数据层修
4. 空间校验与 `check` 通过后，再抽改动处的快照
5. 声音最后做，落点全取节拍
6. 渲染一次，从成片抽帧复核改过的地方

## 8. 已知局限

- 空间校验只管地面占地，四肢与绳线仍需人工看
- 群众动作少，基本站着，复杂的群体走位尚未验证
- 写实造型、带表情的面部尚未尝试，本文的骨骼做法不一定撑得住
