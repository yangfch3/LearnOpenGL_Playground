# N7「矩阵」SPEC · 下集

通用部分（目标、规则、观感、相机、声音、工程、校验、流程）见 [SPEC-上](SPEC-上.md) §1–§8，本文只写下集特有的内容与镜头。

## 1. 下集讲法

三栋楼（滤镜、Google、AI）都按同样五步讲，每步一个小标题式的节拍，不写成字幕：

1. **图景**：一句话的心智模型
2. **造**：矩阵或分数是怎么算出来、调出来的（都是在解方程：消元、最小二乘、反复迭代）
3. **用**：数据穿过矩阵得到结果（都是在乘矩阵）
4. **规模**：为什么它在现实里这么厉害
5. **揭开面纱**：一句话祛魅

观众要能感到同一个套路在重复：到第三栋楼（AI）时，他已经知道接下来会讲「怎么造」「怎么用」。

- **进度便签**：每栋楼翻开新页后，纸的右上角贴一张便签，手写「图景 / 造 / 用 / 规模 / 面纱」；进入下一步时红笔勾掉上一步。第二、三栋楼便签一贴上，观众就知道接下来讲什么。便签不进字幕带，不压焦点；讲到 5b、5c 等大块演示时可淡到非焦点
- **标题卡**（上集同款：胶带上的手写大字）只用在大转折：三栋楼的楼名（「滤镜」「搜索」「AI」）、升华前（「最后一个问题」）。每步的小标题由便签承担，不另出标题卡
- 便签是新手法：先做 3a→3b 一次勾选的 10–30s 样片，定下样式再铺开

## 3. 准确性

| 说法 | 依据 / 处理 |
|---|---|
| 最简单的一类滤镜是 3×3 颜色矩阵 | 如 SVG/CSS 的 feColorMatrix、Android ColorMatrix；字幕说「最简单的滤镜」，不说所有滤镜都是 |
| 手机出厂用色卡和最小二乘定出颜色校正矩阵 | 相机成像流程（ISP）的常见做法；字幕用「常用」级别的措辞，实现前查一条可引用出处写进探针记录 |
| 24 色块色卡 | ColorChecker Classic；色块颜色用公开 sRGB 参考值并注明出处，否则标「示意」 |
| PageRank 是离线算好、与查询无关的分数 | Brin & Page 1998 论文 *The Anatomy of a Large-Scale Hypertextual Web Search Engine* |
| 1998 年约 2400 万个网页；如今「数千亿个网页」 | 前者出自同一论文；后者出自 Google「How Search Works」页面 |
| 如今的排名综合了很多信号 | 纸上小字注明，避免误导为「Google 至今只靠 PageRank」 |
| GPT-3：1750 亿参数、约 3000 亿词元训练、96 层、每个词元 12288 个数 | Brown et al. 2020 |
| DeepSeek-V3：6710 亿参数、14.8 万亿词元训练 | DeepSeek-V3 技术报告 2024 |
| Claude | 参数未公开，不标数 |
| 「压缩」 | 类比，有出处（DeepMind 2023 *Language Modeling Is Compression*）；字幕说「压进」「解码出最可能的下文」，不说「AI 就是解码器」 |
| 「涌现」 | 有争议；只说「能力明显跃升」 |
| 超算排名比的是解方程组 | TOP500 用 HPL 基准：解稠密线性方程组 Ax = b |
| 模型名 | 只用文字 GPT、Claude、DeepSeek，三者总是一起出现；不用 logo |

### 3 滤镜（约 100s）

| 节拍 | 约时长 | 画面 | 字幕 |
|---|---|---|---|
| 3a 图景 | 20s | 手机里一张照片（程序生成的风景，可复用 N6 build.py 的生成法）；约 1500 个像素飞出屏幕，落进立在本子上的 RGB 立方体（三维段 4），成一团彩色点云；三条棱标「红」「绿」「蓝」 | 「手机修图，滤镜是怎么回事？」「每个颜色是 3 个数：红、绿、蓝」「整张照片，是颜色空间里的一团点」 |
| 3b 造 | 30s | 纸上一张 24 色块色卡；手机「拍」它：拍出的每块颜色与真实颜色在立方体里各是一个点，两点之间连一根红线（偏差）；纸上写出「每块 3 个方程 × 24 = 72 个方程，9 个未知数 → 最小二乘」；红线逐渐缩短（回扣 1f 的小方块），纸角的总偏差数跟着变小；得到一个 3×3 矩阵 | 「手机出厂前，常先拍一张色卡」「拍出的颜色，和真实颜色有偏差」「解出的 3×3 矩阵，叫「颜色校正矩阵」」 |
| 3c 用 | 20s | 换成一个暖色滤镜矩阵；立方体里的点云整体挪动、扭斜，手机里的照片同步变暖；纸角写出 3×3 矩阵 | 「最简单的滤镜，也是这样一个 3×3 矩阵」「每个像素乘一次，整团颜色一起挪」 |
| 3d 规模 | 15s | 一道扫描线从照片顶到底扫过，计数贴在扫描线末端，跟着跳到 1200 万 | 「每个像素，都要乘一次」 |
| 3e 面纱 | 15s | 先乘逆矩阵：点云回到原位（撤销）；再按「黑白」：点云压成灰色对角线（上集 2e 的压扁）；两个色相不同、亮度相同的像素（一红一绿）落到同一个灰点，纸上标「同一种灰」；再按撤销，点不动 | 「乘一个「逆矩阵」，滤镜就能撤销」「可黑白，把颜色压成了一条线」「AI 给老照片上色，其实是在猜」；批注「（怎么猜？最后一栋楼揭晓）」 |

- 对应：3a、3c 中，照片里点一个像素，立方体里它那一点同时亮起；3b 中每块色卡与立方体里它的两个点同时亮起
- 文字演：3e 字幕里的「黑白」两个字，随点云压扁一起褪成灰色
- 数据：CCM 示例由「真实颜色 × 某个偏差矩阵 + 小噪声」生成拍出的颜色，最小二乘解回的矩阵与偏差矩阵之逆误差 < 0.02；暖色滤镜行列式 > 0.5；黑白矩阵每行 = (0.299, 0.587, 0.114)，行列式 = 0；那两个像素的灰度差 < 1、色相差 > 90°
- 声音：点云飞入如细沙（细碎音效，压低、去掉刺耳的高频）；拍色卡一声快门；红线缩短时持续音下行；按「黑白」时与上集 2e 同一声闷响

### 4 Google（约 120s）

| 节拍 | 约时长 | 画面 | 字幕 |
|---|---|---|---|
| 4a 图景 | 20s | 翻页，标题卡「搜索」。纸上画一个老式搜索框，结果列表被一个通篇重复关键词的网页占了第一名（示意）；随后网页之间长出箭头：链接即投票 | 「1998 年以前，搜索结果常被垃圾网页占满」「谁把关键词重复得多，谁就排前面」；批注「（这招现在不灵了）」；「Google 的想法：让网页互相投票」 |
| 4b 造 | 50s | 5 个网页 A–E 与链接（示意）；纸上把「被重要的链接就重要」写成首尾相接的一圈字；逐个写出 5 个方程，再加「A + B + C + D + E = 1」；红笔解出 5 个分数；接着换另一种算法：每页先 0.2，分数写在各节点旁，沿链接像水一样流、一轮一轮跳动，停住后与红笔解出的 5 个数并排，打「=」 | 「被重要的网页链接，就更重要」「绕圈了？写出来，就是一个方程组」「几十亿个未知数解不动：那就一轮轮投票」「投到不再变的这组数，叫「特征向量」」 |
| 4c 用 | 20s | 搜索框里输入「鸡兔同笼」：先挑出含这个词的网页，再按算好的分数排序 | 「分数提前算好；你一搜，就按分数排」 |
| 4d 规模 | 15s | 5 个网页的图向外扩成满纸的点；纸角计数随点扩散，从「1998 年 2400 万」跳到「如今数千亿」 | 「网页越多，越只能一轮轮投票」 |
| 4e 面纱 | 15s | 纸上贴出论文标题；角落小字「如今排名综合了很多信号」「真实算法另加随机跳转，此处省略」 | 「Google 起家的秘方，写在一篇公开的论文里」 |

- 对应：每写出一个方程，它所属的网页节点同时亮起；投票停住时，节点旁的分数与红笔解出的分数一一同时亮
- 文字演：「被重要的链接就重要」写成一圈，写到首尾相接时红笔圈一下，字幕跟上「绕圈了？」
- 数据：5 页链接图强连通，方程组有唯一解，5 个分数两两不同；迭代 30 轮内与解的最大差 < 1e-4；4c 的排序与分数一致
- 声音：每轮投票一阵细小的水流声（细碎音效，压低），越来越轻；收敛时一声清音

### 5 AI（约 190s）

神经网络的「层」画成一叠方格纸（三维段 5）：每张纸是一个权重矩阵，纸上格子的深浅是数值。全段在同一叠纸上演。

| 节拍 | 约时长 | 画面 | 字幕 |
|---|---|---|---|
| 5a 图景 | 35s | 纸上画一个手机输入法：输入「床前明月」，候选栏出现「光」；再把上集 1f 的外卖图缩小贴在纸角，旁边小字「100 单 → 2 个数」；然后一股文字洪流（各种语言的句子）灌进那叠方格纸，另一端一个字一个字流出 | 「先看输入法：它在猜你下一个字」「AI 做的是同一件事，只是猜得极准」「海量文字，被压进千亿个数里」「回答时，再一个字一个字解码出来」 |
| 5b 造：训练 | 60s | ① 一个字「月」变成一竖列数（2a 的鸡箭头式的「一串数」），纸角小字「准确说是「词元」」；② 这一列穿过第一张纸：取出纸上一行，和这一列对应相乘再相加，得到一个数，纸角写「就像 2x + 4y」；整张纸做完就得到新的一列；③ 负数被压成 0，纸上小字「弯折」，送进下一张；④ 起初每张纸是随机的灰噪点，输出猜「猫」，正确答案「光」，两者差距画成 1f 那样的红笔方块（损失）；⑤ 每张纸上的格子朝方块变小的方向微调一点（格子深浅轻轻变化）；⑥ 快进：成千上万句话流过，纸角的损失曲线从高处下降，最后变平，损失值贴在曲线末端跟着变；纸上的格子不再变化 | 「每个字，先变成一串数」「每一层，都是一次矩阵乘法」「一开始全是随机数：乱猜」「和正确答案的差距，叫「损失」」「每个数都朝损失变小的方向，挪一点点」 |
| 5c 用：推理 | 45s | 纸上输入「鸡兔同笼怎么解？」；问题加上已经写出的字变成一列列数，穿过那叠纸；出口处是一排概率柱（「设」最高，示意）；「设」落到答案行，再接上，再算：答案逐字长出「设鸡有 x 只……」 | 「你的问题，也变成一串串数」「穿过一层层矩阵，算出下一个字的可能性」「挑一个，接在后面，再算一遍」；答案长出时批注「（眼熟吗？）」 |
| 5d 规模 | 30s | 那叠纸越叠越高、越来越宽；旁边并列三个文字名 GPT、Claude、DeepSeek，只在有公开数字的下面标小字（GPT-3：1750 亿参数、96 层；DeepSeek-V3：6710 亿参数、14.8 万亿词元训练） | 「GPT、Claude、DeepSeek，都是这样的大模型」「文字越喂越多，矩阵越来越大」「大到一定程度，能力明显跃升」 |
| 5e 面纱 | 20s | 那叠纸散开，落回成一张张普通的方格纸；纸角画一块显卡芯片，里面成千上万个小格同时亮 | 「没有魔法：一层层矩阵乘法」「显卡，就是为这种乘法造的」 |

- 对应：5a 外卖图的 100 个点收成 2 个数，与文字洪流灌进纸叠同步演；5b「一行乘一列」时，纸角贴上集 2b 的矩阵缩略，它的一行与当前这一行同时亮
- 文字演：5c 答案行的字从概率柱顶上落下，落定即成答案的一字
- 数据：5b 的「一行乘一列」用真实计算的小例子（如 8 维）；损失曲线由一个小网络的真实训练日志生成或标「示意」；5c 的概率为示意，标「示意」
- 声音：主题换到低音合成垫 + 钢琴；训练快进时一串加速的细碎音（压低），损失变平时归于一个长音；推理时每落一个字一声

### 7 倒放（约 40s）

- 结构：约 12 段倒放片段，从下集一路倒回上集，每段取该段一个动作的 1.5–3s 原片倒着播（2–8 倍速），段与段之间 0.4s 交叉过渡；片段越来越短（节奏加快），最后一段放慢到 1 倍速并停住
- 片段顺序：5c 逐字生成 → 5b 损失曲线 → 4b 投票 → 3e 点云压扁 → 2-post 楼群缩回地面 → 2e 格纸由扁复原 → 2a 箭头逐根拆回 → 1f 点飞回 → 1d 平面收回 → 1c 小点滑回 → 1b 字迹被倒着擦掉 → 1a 动物放下脚
- 落点：停在上集 1a「35 个头，94 只脚」写完的那一帧，画面逐像素一致（首尾同一帧，check 里比对）
- 光敏：任意 1 秒内亮度大跳变 ≤ 3 次；倒放期间每帧位移超限就加运动模糊
- 声音：主题倒着放，音高随倍速升高，叠一层倒带声；落点处静音一拍

### 8 结尾（约 20s）

- 画面：笼子静止；铅笔在下方写「35 头，94 足」；旁边淡淡浮现 2×2 矩阵 1 1 / 2 4；最后片名「矩阵」用霞鹜文楷手写写出
- 字幕：「一切，从数笼子里的脚开始」
- 声音：八音盒奏一句开头的主题，停在主音

## 5. 下集校验（在上集 §7 之外）

- 3 段：CCM 解回误差、暖色滤镜行列式、黑白行列式为 0、同灰两像素的条件
- 4 段：方程组唯一解与迭代收敛一致
- 5 段：5b 小例子的乘加结果与纸上写的数一致
- 7 段：落点帧与上集对应帧像素差为 0；倒放各片段取到的源时刻都在对应段内
- 新元素的空间校验（与元素同一轮补上）：进度便签、标题卡、批注、跟着过程走的读数（扫描线计数、节点分数、损失值）、立方体与地球仪上的文字，都不出纸面或画面、不进字幕带、不压当时的焦点
