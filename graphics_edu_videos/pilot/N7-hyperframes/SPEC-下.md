# N7「矩阵」SPEC · 下集

通用部分（目标、规则、观感、相机、声音、工程、校验、流程）见 [SPEC-上](SPEC-上.md) §1–§8，本文只写下集特有的内容与镜头。

## 1. 下集讲法

三栋楼（滤镜、Google、AI）都按同样五步讲，每步一个小标题式的节拍，不写成字幕：

1. **图景**：一句话的心智模型
2. **造**：矩阵或分数是怎么算出来、调出来的（都是在解方程：消元、最小二乘、反复迭代）
3. **用**：数据穿过矩阵得到结果（都是在乘矩阵）
4. **规模**：为什么它在现实里这么厉害
5. **揭开面纱**：一句话祛魅

观众要能感到同一个套路在重复：到第三栋楼（AI）时，他已经知道接下来会讲「怎么造」「怎么用」。

- **进度便签**：每栋楼翻开新页后，纸的右上角贴一张便签，手写五个课本式小标题（三栋楼同一套）：「1. 原理」「2. 求解」「3. 应用」「4. 计算量」「5. 小结」；当前一步前面一个红箭头。上面的「图景、造」等只是制作用的节拍名，不上画面
- **文案**：按创作原则 §3-23 平实陈述。下文 4–8 段的字幕原文是旧稿，有设问、揭秘口吻、排比，做到该段时先按此改写，再排时间
- **看一眼便签**（3c 起）：换步时镜头去看一眼便签，红笔勾掉上一问、箭头移到下一问，读完回到工作机位；其余时间便签在画外。同一个动作每次都一样，成为换步的仪式
- **标题卡**（上集同款：胶带上的手写大字）只用在大转折：三栋楼的楼名（「滤镜」「搜索」「AI」）、升华前（「最后一个问题」）。每步的小标题由便签承担，不另出标题卡

## 1.1 制作范式（3c 起试行，看片后定是否推广、是否回改 3a–3b）

- **时间线以画面动作为主轴**：动作按拍排，字幕挂到动作的时间窗上（`say(t0=…)`），阅读时长由 build 断言；不再「一条字幕推一段动作」
- **取景跟着焦点走**：每栋楼一个工作机位，焦点物（3 段是手机、立方体、矩阵）占满画面，纸上字约 30px/格（原全景约 19px/格）；用完的推导淡去，不常驻
- **空间校验**：物体要么整个在画内、要么整个在画外；镜头停住时被画框切到才算错。立体文字之间互不相压

### 世界

### 文字（创作原则 §3）

- **字幕只讲画面讲不出的那句话**：纸上已经写了的（如「就像 2x + 4y」）不进字幕；读数（计数、分数、损失值）写在画面里，跟着过程变
- **点题词**：颜色校正矩阵、逆矩阵、特征向量、损失、词元，在被命名的那一刻与上集「矩阵」「行列式」同样处理：红字加荧光笔底，字幕与纸上同词同样式
- **文字自己演**：每栋楼一处，见各段「文字演」
- **批注**：全集 3 处，见 3e、4a、5c
- **对应**：同一个东西有两种画法时两处同时亮，见各段「对应」

### 3 滤镜（约 100s）

| 节拍 | 约时长 | 画面 | 字幕 |
|---|---|---|---|
| 3a 图景 | 20s | 手机里一张照片（程序生成的风景，可复用 N6 build.py 的生成法）；约 1500 个像素飞出屏幕，落进立在本子上的 RGB 立方体（三维段 4），成一团彩色点云；三条棱标「红」「绿」「蓝」 | 页眉「手机修图用的滤镜」；「每个颜色是红、绿、蓝 3 个数」「照片的每个像素都是立方体里的一个点」 |
| 3b 造 | 30s | 纸上一张 24 色块色卡；手机「拍」它：拍出的每块颜色与真实颜色在立方体里各是一个点，两点之间连一根红线（偏差）；纸上写出「每块 3 个方程 × 24 = 72 个方程，9 个未知数 → 最小二乘」；红线逐渐缩短（回扣 1f 的小方块），纸角的总偏差数跟着变小；得到一个 3×3 矩阵 | 「手机出厂前，通常会拍色卡校准颜色」「拍出的颜色和色卡的真实颜色有偏差」「解出的 3×3 矩阵叫「颜色校正矩阵」」 |
| 3c 用 | 19s | 看一眼便签；3b 的推导淡去、色卡滑走，手机挪到书脊上与立方体同框，屏幕上沿出现工具条「暖色 / 黑白 / ↶ 撤销」。点「暖色」：纸上写出暖色矩阵；照片变暖，同时立方体乘这个矩阵变成斜的平行六面体（带 3×3×3 的格，上集 2g 的样子），点云跟着它一起挪；原立方体退成参照 | 「最简单的一类滤镜就是一个 3×3 矩阵」「整个颜色空间随这个矩阵一起变形」 |
| 3d 规模 | 19s | 看一眼便签；一道扫描线从照片顶扫到底，扫过的每一行像素都落进立方体、先大后小亮一下（点云由稀变密）；纸上读数「像素 N 万」跟着扫描线数到 1200 万；手机快门一响 | 「每个像素都要乘一次这个矩阵」；批注「（不加滤镜，每张照片也会先乘校正矩阵）」 |
| 3e 面纱 | 35s | 看一眼便签；点「撤销」：矩阵换成它的逆（标点题词「逆矩阵」），平行六面体退回立方体；照片上圈出一朵红花、一片绿草；点「黑白」：平行六面体压成灰色对角线（上集 2e 的压扁），两个点落到同一处，立方体里写「同一种灰」；再点撤销，按钮抖一下、什么都不动，矩阵下红笔写「行列式 = 0」，灰点旁换成红字「红？绿？」 | 「再乘它的「逆矩阵」，就能撤销滤镜」「黑白滤镜把所有颜色压到一条线上」「所以给黑白老照片上色，只能靠推测」；批注「（AI 怎样推测，第三栋楼里讲）」 |

- 对应：3a 中照片里点开的像素与立方体里它那一点同时亮起；3b 中每块色卡与立方体里它的两个点同时亮起；3c、3e 中照片上的圈与立方体里放大的点同时亮
- 文字演：3e 字幕里的「黑白」两个字，随点云压扁一起褪成灰色
- 数据：CCM 示例由「真实颜色 × 某个偏差矩阵 + 小噪声」生成拍出的颜色，最小二乘解回的矩阵与偏差矩阵之逆误差 < 0.02；暖色滤镜行列式 > 0.5，元素非负、每行和 ≤ 1（立方体映进自身，不出界）；黑白矩阵每行 = (0.299, 0.587, 0.114)，行列式 = 0；红花与绿草（原图像素）灰度差 < 1、色相差 > 90°
- 声音：点云飞入、扫描都如细沙（细碎音效，压低、去掉刺耳的高频）；拍色卡、3d 各一声快门；红线缩短时持续音下行；按「黑白」压扁到底一声闷响（上集 2e 同款），随后安静一拍；按了没反应是两声闷的轻响

### 4 Google（约 120s）

> 已定改动（下表待按此重写）：4b、4e 改用 3 个网页 A→B、A→C、B→C、C→A、C→B，回扣上集 1d。方程组是三个平面交于一点，解 (0.222, 0.333, 0.444)；三个分数和为 1，所以每投一轮，分数点都在三角形 x + y + z = 1 上跳一下，从任一角出发 12–14 轮落到同一点（第二特征值 −0.5，在目标两侧来回跳、越跳越近）；过原点和这一点的那条线就是机器开了也不转向的方向：「特征向量」。5 个网页的水流画面留给 4a 或 4d

|---|---|---|---|

### 7 倒放（约 40s）

- 做法（已定）：直接取两集成片的片段，用 ffmpeg 倒放、变速，帧混合当运动模糊；落点帧就是上集那一帧。不再要求下集能按段内时刻重画上集
- 结构：约 12 段倒放片段，从下集一路倒回上集，每段取该段一个动作的 1.5–3s 原片倒着播（2–8 倍速），段与段之间 0.4s 交叉过渡；片段越来越短（节奏加快），最后一段放慢到 1 倍速并停住
